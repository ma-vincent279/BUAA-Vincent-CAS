## 一、相机基础：从三维到二维

### 1.1 针孔模型【源码事实】

相机把**三维世界**投影到**二维图像**：

```
        物体 (X, Y, Z)                    图像 (u, v)
              │                                │
              │   Z (深度)                     │
              └────────►                       │
                        \                      │
                         \  光心              │
                          \  │                │
                           \ │                │
                            ▓└───────────────►│
                          f │                 │
                        (焦距)
```

**公式**（最简单的一阶模型）：

```
u = 画面中心x + (X / Z) · f
v = 画面中心y − (Y / Z) · f
```

其中 `f` 是**以像素为单位的焦距**（`FX` / `FY`），`Z` 是**深度**（相机到物体的距离）。

### 1.2 内参：`FX / FY / CX / CY`

| 参数 | 含义 | 本项目 |
|---|---|---|
| **`FX`, `FY`** | 水平/垂直方向的等效焦距（像素）| **171.21 px**（两个相等）|
| `CX`, `CY` | 画面中心（像素）| 320, 180（即 640×360 的中心）|

**【源码事实】** 本项目 `FX` 是**算出来的**，不是标定出来的 —— 因为我们只知道"对角线 130°"：

```python
FX = FY = (√(640² + 360²) / 2) / tan(65°) = 171.21 px
#         └── 画面对角线的一半 ──┘   └ 对角线一半的角度 ┘
```

**反过来就能算视场角**：

```python
HFOV = 2 · atan(320 / 171.21) = 123.70°      # 水平视场
VFOV = 2 · atan(180 / 171.21) =  92.87°      # 垂直视场
```

> ⚠️ **注意**：标称的"对角线 130°"是**对角线**方向的视场，
> 而水平/垂直视场分别是 **123.70° / 92.87°** —— 别搞混 ✓

## 二、像素 → 地面偏移（核心公式）

**这是整个视觉伺服的地基。**

### 2.1 基本公式

飞机在高度 `H` 上往下看，桶在画面里偏离中心 `Δu` 像素 ⇒ 桶离飞机正下方多远？

```
地面偏移 = Δu · H / FX
```

**直觉**：同样偏 1 像素，飞得越高，地面上偏得越远 ✓

**【实测数据】** 校验一下：`H = 1.77 m`，`Δu = 2 px`
⇒ `地面偏移 = 2 × 1.77 / 171.21 = 0.021 m = **2.1 cm**` ✓
（我们曾用这个数验证"像素与真值一致"，见 [`../reports/k_accuracy_three_lenses_20261013.md`](../reports/k_accuracy_three_lenses_20261013.md)）

### 2.2 为什么要修正姿态

上面的公式假设"相机正对地面"。但飞机有 **pitch（俯仰）**和 **roll（横滚）** ⇒
画面中心对应的地面点会**偏移**。

**【源码事实】** 本项目的 `camera_pixel_to_level(cx, cy, pitch, roll)` 就是干这个的：
先把像素反投影成**机体系**的射线，再**去掉 pitch/roll**，得到"水平坐标系下的方向"。

> 【经验/建议】**姿态项不能忽略**：`H · tan(pitch)`，在 `H = 1.2 m`、`pitch = 5°` 时约 **10 cm** ✗
> 这是个真实踩过的坑：有一趟实飞 pitch 达 4.2~5.6°，落点整体偏前 11~12 cm。

## 三、广角：为什么用 130°，代价是什么

### 3.1 为什么要广角【源码事实】

投放区是 **5 m × 5 m**。要在**一次进场**里看全它，视野必须够大：

| 高度 | 130° 视野的沿航向覆盖 | 够看 5 m 区吗 |
|---|---|---|
| 5.0 m | 10.5 m | 够 |
| **3.0 m** | **6.31 m** | **够（我们选了 3 m）** ✓ |
| 1.2 m（投放高度）| 2.44 m | 不够（但那时只需要看一个桶）|

⇒ **巡航/搜索高度定 3.0 m**（`CRUISE_HEIGHT`），刚好一次看全 ✓

### 3.2 代价：桶很小【实测数据】

| 高度 | 15 cm 桶的像素尺寸（130°）| 旧 85° 视野 |
|---|---|---|
| 5.0 m | **5.1 px** | 10.5 px |
| 3.0 m | **8.6 px** | — |
| 1.2 m | **21.4 px** | — |

**后果**：
- **±1 px 的检测误差**，在 5 m 处换算到地面就是 **±2.9 cm** ✗
- 直径分类误差 ±2 cm ⇒ 我们因此加了"直径身份门"（见第五节）
- 为此把巡航高度从 5 m 降到 3 m（8.6 px 比 5.1 px 好得多）✓

## 四、"近大远小"与直径反推（**含一次真实的自我纠错**）

### 4.1 问题

我们要**按直径识别桶**（15/20/25 cm）。但桶离得远就小、离得近就大 ——
**怎么区分"这是个小桶"还是"这是个远的大桶"？**

### 4.2 答案：除以深度，透视就被抵消了

```
D_反推 = 像素边长 × depth / FX
              └── 除的正是那个"距离" ──┘
```

桶离得远 ⇒ 像素变小，但 depth 变大 ⇒ **两者精确相消** ✓

**【实测数据】** 对 3 种桶径 × 5 个高度，往返误差 **0.0000 cm** ✓

### 4.3 ⚠️ 但关键在：`depth` 用哪个"距离"？

**【源码事实】** 我们的仿真检测器是**用垂直高度**造框的：

```python
radius_px = fx · 桶半径 / dz          # ← dz 是垂直高度, 不是斜距!
```

⇒ 所以反推也**必须用垂直高度**，这样往返才精确 ✓

### 4.4 【实测数据】一次自我纠错：我差点改错

当时推理是："离画面中心越远的桶，真实**斜距** `√(H²+r²)` 越大，所以 `depth` 该用斜距。"

**听起来对，实则错** ✗ 离线核对三种写法：

| 反推用的 depth | 最大往返误差 | 判定 |
|---|---|---|
| **垂直高度** ← 正确 | **0.00 cm** | ✓ 精确 |
| 斜距 `√(H²+r²)` ← 我改的 | **14.15 cm** | ✗ 破环 |
| `√(H²+r²)²/H` | 41.67 cm | ✗ 破环 |

**具体**：`H = 1.2 m`、偏心 `2.0 m` 时，15 cm 桶被斜距公式算成 **29.2 cm** ⇒
与目标记录差 14 cm ≫ 容差 3 cm ⇒ **门会把目标自己拒收** ✗

⇒ **已撤回**，并把这条做成**回归护栏**写进验收（断言"斜距反推必须产生 >10 cm 偏差"）✓

> **【经验/建议】教训**：**反推模型必须与正向模型一致**。
> "物理上更对"的公式，如果和检测器用的不一致，反而会错 ✗

## 五、画面里有三个桶怎么办：直径身份门（D36）

### 5.1 问题

130° 广角下，**三个桶经常同时入画** ✗
检测器返回一堆框，怎么知道**哪个框是我们要投的那个桶**？

### 5.2 解法【源码事实】

选桶时，我们记录了目标桶的**直径**（用上面的公式反推）。
之后每一帧收到的新框，都做一次检查：

```
|框反推的直径 − 目标记录直径| ≤ K_DIA_IDENTITY_TOL (3 cm)   ⇒ 才采信这个框
```

⇒ 隔壁那个 20 cm 的桶会被拒收 ✓（因为 20 − 15 = 5 > 3）

**【实测数据】** 累计挡下 **159 次**（平均 **14.5 次/轮**）—— 说明**串桶场景每轮都在发生**，
这个门是必需的 ✓

### 5.3 余量有多大【实测数据】

| 项 | 值 |
|---|---|
| 两档桶径的最小间隔 | **5 cm**（15→20→25）|
| 门限 | **3 cm** |
| **区分余量** | **只有 2 cm** |

⇒ 说明这个门**不能设得太松**（会串桶），也不能太紧（会拒收目标）✓

## 六、检测器：仿真 vs 真机

| | 仿真 | 真机 |
|---|---|---|
| 节点 | `yolov8_bucket_detector.py` | `see.py` |
| 默认方式 | **GT 投影**（`sim_gt_direct:=true`）| **YOLOv8**（TensorRT）|
| 框怎么来 | 由**桶真值坐标 + 飞机 EKF 位置**投影算出来 | 神经网络推理真实图像 |
| 延迟 | 0 | ~20 ms |
| 分辨率 | 640×360 | 1920×1080 全帧缩放（**不裁剪**）|

### ⚠️ 6.1 【源码事实】仿真检测器是"EKF 参照"的 —— 这是最重要的认知

```python
px = 画面中心x + ((桶真值_x − EKF位置_x) / 垂直高度) · fx
```

而任务节点的反投影是它的**逆运算** ⇒ `桶估计 ≡ 桶真值`（**恒等**）✓

⇒ **整条视觉链测的是「EKF 眼里的桶偏移」**，
⇒ **它对 EKF 自身的绝对估计偏差「结构性失明」** ✗

**后果**：仿真里无论我们怎么调伺服，都消不掉飞控 EKF 的偏差（实测约 8 cm）
⇒ **仿真分数不能代表真实精度** ✓

📄 完整推导：[`../reports/k_accuracy_three_lenses_20261013.md`](../reports/k_accuracy_three_lenses_20261013.md)

## 七、相机标定（实机需要）【待验证】

仿真里 `FX` 是"算"出来的，但**实机的相机需要标定**：

| 标定项 | 方法 | 状态 |
|---|---|---|
| **内参**（FX/FY/CX/CY + 畸变）| 棋盘格 + `cv2.calibrateCamera` | ⏳ **【待验证】** 本项目实机未做严格标定 |
| **外参**（相机相对机体的安装角）| 静态测量（水平仪 + 卷尺）| ⏳ 未做 |
| **求交平面** | `K_TARGET_PLANE_H = -0.278`（相对起飞点平面下移量）| 【源码事实】已有值 |

> 【经验/建议】**好消息**：我们的实飞数据表明**相机反投影是准的** ——
> 【实测数据】2026-09-23 那趟把节点日志的"等效地面误差"与 ULog 的"飞机 vs 设定点"逐点对齐，
> **corr = 0.90 / 0.95，中位比值 1.01 / 1.10** ⇒ 误差 100% 来自"飞机没停在桶上方"，
> **不是相机标定问题** ✓（这排除了一个长期怀疑项）

⇒ 所以**优先做的是"飞机停稳"，不是"相机标定"** ✓

## 九、术语表

| 术语 | 意思 |
|---|---|
| **内参 / 外参** | 内参 = 相机自己的（焦距、主点、畸变）；外参 = 相机相对机体的安装位置与角度 |
| **`FX` / `FY`** | 以**像素**为单位的等效焦距 |
| **HFOV / VFOV** | 水平 / 垂直视场角 |
| **反投影** | 从像素反推"这个世界里在哪"（我们的核心运算）|
| **`rim_body`** | 桶在**机体坐标系**下的偏移（释放残差就是它的模长）|
| **`depth`** | 相机到物体的距离（**本项目用垂直高度**）|
| **GT（Ground Truth）** | 真值 |
| **`sim_gt_direct`** | 仿真检测器的一个参数：直接发 GT 投影的框，跳过神经网络 |
