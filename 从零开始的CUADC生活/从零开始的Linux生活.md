## 二、终端怎么开

`Ctrl + Alt + T` ✓（最常用）

**终端里你会看到这样一行**：

```
vincent@wp:~/SITL$
   ↑      ↑  ↑
  用户名  主机名  当前所在目录（~ 表示「家目录」）
```

**最后那个 `$`** 表示"普通用户"（`#` 表示 root）✓

## 三、必须会的 20 个命令

### 3.1 我在哪 / 有什么

```bash
pwd                 # 我现在在哪个目录 (print working directory)
ls                  # 列出当前目录的文件
ls -la              # 详细列出（含隐藏文件、权限、大小）
cd ~/SITL           # 进入某个目录 (change directory)
cd ..               # 回上一级
cd -                # 回上一次的目录
cd                  # 直接回家目录
```

**【经验/建议】`cd` + `Tab` 是最高频组合** —— 敲 `cd ~/SI` 然后按 `Tab`，会自动补全 ✓

### 3.2 看文件内容

```bash
cat 文件            # 全部打印出来（小文件用）
less 文件           # 分页看（大文件用；按 q 退出，/ 搜索）
head -20 文件       # 看前 20 行
tail -20 文件       # 看后 20 行
tail -f 日志        # ★ 实时跟踪（看运行中的日志用，Ctrl+C 退出）
```

### 3.3 找东西

```bash
find . -name "*.py"              # 找文件
grep -rn "关键词" .              # ★ 在文件内容里搜（最常用）
grep -rn "K_RELEASE" SITL/       # 在某个目录里搜
```

**【经验/建议】** `grep -rn` 是改代码时**最有用的一条命令** ——
不知道某个参数在哪定义？`grep -rn "K_RELEASE_MIN_M" .` ✓

### 3.4 改东西

```bash
nano 文件           # 简单的编辑器（Ctrl+O 保存，Ctrl+X 退出）★ 新手推荐
vim 文件            # 强大但难学（`:wq` 保存退出，`:q!` 不保存退出）
```

### 3.5 权限（**最容易卡住的地方**）

```bash
sudo 命令           # 以管理员身份执行 ★
chmod +x 脚本.sh    # 给脚本加"可执行"权限
```

**【经验/建议】** Linux 的权限规则很简单：**改系统的东西要 `sudo`，改自己家的不用** ✓
看到 `Permission denied` ⇒ 八成是忘了 `sudo` ✓

### 3.6 复制移动删除

```bash
cp 源 目标           # 复制
cp -r 目录 目标      # 复制整个目录（-r = 递归）
mv 源 目标           # 移动 / 改名
rm 文件              # 删除（⚠️ 没有回收站！）
rm -rf 目录          # ⚠️⚠️ 强制删目录，**极其危险，敲之前先看清路径**
```

> ⚠️ **【经验/建议】`rm -rf` 是 Linux 上最危险的命令**。
> 敲之前**务必看清楚路径**，特别是路径里有变量的时候 ✗

### 3.7 看进程

```bash
ps aux | grep px4    # 看 px4 进程还在不在
top                  # 实时看谁在吃 CPU（q 退出）
kill 1234            # 结束 PID 为 1234 的进程
pkill -9 -x px4      # 按名字杀进程
```

> ⚠️ **【经验/建议】`pkill -f "xxx"` 会匹配到你自己！**
> 如果你的命令行里正好含这个字符串，**它会把你自己的终端也杀掉** ✗
> ⇒ 清理进程一律**写进脚本文件**再执行 ✓

## 四、几个 Linux 特有的概念（不搞懂会一直踩坑）

### 4.1 路径：绝对 vs 相对

| 写法 | 含义 |
|---|---|
| `/home/vincent/SITL` | **绝对路径**（从根 `/` 开始）|
| `~/SITL` | `~` = 家目录 = `/home/vincent` ✓ |
| `./scripts/test_k.sh` | **相对路径**（`.` = 当前目录）|
| `../docs/` | `..` = 上一级目录 |

### 4.2 大小写敏感 ✗

Linux **严格区分大小写**：`README.md` ≠ `readme.md` ✗

### 4.3 换行符

Windows 的文件用 `\r\n`，Linux 用 `\n` ✗
**Windows 编辑过的脚本在 Linux 上跑会报 `bad interpreter`** ✗
⇒ 解决：`sed -i 's/\r$//' 脚本.sh` 或 `dos2unix 脚本.sh`

### 4.4 `source` ≠ 执行

| 写法 | 含义 |
|---|---|
| `bash 脚本.sh` | **执行**：在**子 shell** 里跑，脚本里的变量**不会影响你的终端** |
| `source 脚本.sh` | **加载**：在**当前 shell** 里跑，变量**会生效** ✓ |

**【源码事实】** 例如：

```bash
source /opt/ros/humble/setup.bash      # 让当前终端认识 ros2 命令
source install/setup.bash              # 让你自己的工作空间生效
```

⇒ **新开一个终端，就要重新 `source`** ✓（这是新手最常见的困惑："我明明装好了，为什么 `ros2` 找不到？"）

### 4.5 管道与重定向

```bash
命令 > 文件           # 把输出写进文件（覆盖）
命令 >> 文件          # 追加
命令 2>&1 | tee 日志  # ★ 同时显示在屏幕 + 存进文件（本项目启动脚本就用这个）
命令1 | 命令2         # 管道：把前一个的输出给后一个
```

## 五、本项目里你会用到的操作

### 5.1 看仿真在干什么

```bash
tail -f runs/k_33_*/mission.log          # 实时看任务日志
grep "DROP" runs/k_33_*/mission.log      # 只看投放那几行
grep -c "触发方式=达标即投" runs/k_33_*/mission.log   # 数一数有几投是"达标即投"
```

### 5.2 清残留进程（**每轮仿真前必做**）

```bash
bash scripts/cleanup_sim.sh          # 别手动 pkill ✗
```

### 5.3 看磁盘还剩多少

```bash
df -h /              # 看根分区
du -sh */ | sort -rh | head    # 看哪个目录最大
```

**【经验/建议】** 仿真跑多了**日志会把磁盘吃满** ✗ 定期清：

```bash
rm -rf runs/*        # 清仿真产物（确认不需要了再删）
```

### 5.4 找某个参数在哪定义的

```bash
grep -rn "K_RELEASE_MIN_M" SITL/ src/ fly/
```

## 六、动手练习

1. **开终端**（`Ctrl+Alt+T`），依次敲 `pwd` `ls` `ls -la`，看看输出
2. **用 `Tab` 补全**：敲 `cd ~/SI` 按 `Tab`，看它自动补全成什么
3. **`grep` 一次**：在仓库里找出 `K_RELEASE_CONFIRM` 定义在哪
4. **`tail -f` 一次**：跑一轮仿真（`bash scripts/test_k.sh`），另开一个终端 `tail -f` 日志，**实时看飞机在干什么**
5. **故意制造一个 `Permission denied`**：`cat /etc/shadow` ⇒ 然后加 `sudo` 再试
6. **`rm -rf` 的教训**：在**一个新建的测试目录**里试试 `rm -rf`，体会它有多快 ✗
   （⚠️ 只在测试目录里试，别在项目目录里试！）
