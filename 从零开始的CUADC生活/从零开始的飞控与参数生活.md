## 一、PX4 是什么，和 ArduPilot 什么关系

| | **PX4** | **ArduPilot** |
|---|---|---|
| 我们的项目 | ✅ 用的是这个 | — |

⇒ ⚠️ **所以"直接跑他们的代码"做不到** ✗ ——

## 二、参数系统

### 2.1 参数是什么

飞控有**上千个可调参数**，存在飞控的存储里，掉电不丢。例如：
- 机型（`SYS_AUTOSTART`）
- 传感器校准值
- 控制环增益（`MPC_*`）
- 估计器配置（`EKF2_*`）
- 串口波特率（`SER_*`）

### 2.2 怎么读我们的参数【源码事实】

库里有**两份原件**（从实机导出的）：

| 文件 | 行数 | 用途 |
|---|---|---|
| `docs/项目全解/硬件/PX4参数_GPS.params` | 1055 | 普通 GPS 配置 |
| `docs/项目全解/硬件/PX4参数_RTK.params` | **1199** | **RTK** 配置（推荐看这份，更全）|

**格式**（tab 分隔）：
```
sysid␉compid␉参数名␉值␉类型
1␉1␉BAT1_N_CELLS␉6␉6
```

**用命令行读**（比手翻 1199 行快）：
```bash
awk -F'\t' '$3=="BAT1_N_CELLS"{print $4}' docs/项目全解/硬件/PX4参数_RTK.params
```

### 2.3 怎么在 QGC 里载入

**QGroundControl → Parameters → Tools → Load from file** → 选 `.params` 文件 → 重启飞控 ✓

> ⚠️ **载入前先核对机型**：`SYS_AUTOSTART` 必须与你的机架一致，否则控制参数全错 ✗

## 四、★ EKF：为什么它决定了我们的精度上限

### 4.1 EKF 是什么

**EKF = Extended Kalman Filter（扩展卡尔曼滤波）**，飞控用它来回答一个问题：

> **"我现在到底在哪？"**

它融合这些传感器：

| 传感器 | 提供什么 | 特点 |
|---|---|---|
| IMU（加速度计+陀螺）| 加速度、角速度 | 频率高、短期准、**长期会漂** |
| 气压计 | 高度 | 慢、受气流影响 |
| 磁罗盘 | 航向 | 受磁干扰 |
| **GPS / RTK** | **绝对位置** | 频率低、有噪声、可能丢星 |

⇒ **EKF 把这些"都不完美"的传感器融合成一份"尽量准"的位置估计** ✓

**关键**：飞控报给我们的 `/fmu/out/vehicle_local_position_v1`，**是 EKF 的估计值，不是真值** ✗

### 4.2 【实测数据】我们的 EKF 有多少偏差

这是本项目**最重要的一个发现**：

| 量 | 值 |
|---|---|
| EKF 报的位置 vs Gazebo 真值（x 方向）| −5.5 ~ +2.6 cm，**均值 ≈ 0**（无系统偏移）|
| **EKF 报的位置 vs 真值（y 方向）** | **−13.2 ~ −3.8 cm，均值 ≈ −8 cm** ✗ |

而且：**`t=0`（飞机还在生成点上）时两套坐标是对齐的** ⇒
⇒ **这个约 8 cm 的偏差是"飞行过程中长出来的"**，
⇒ 它是 **PX4 SITL 的 EKF 估计偏差**，**不是**参考系固定错位、也**不能靠减一个常数修掉** ✗

### 4.3 为什么这对我们影响巨大

| 事实 | 后果 |
|---|---|
| 仿真里"落点"取的是 **飞机自报的 EKF 位置** | EKF 偏了 ⇒ 判分就认为"脱靶" ✗ |
| 仿真检测器也是**用 EKF 位置造框**的 | 视觉链看不见 EKF 的绝对偏差 ⇒ **结构性失明** ✗ |
| ⇒ 仿真分数 ≈ EKF 偏差 ⊕ 释放残差 | **仿真分数不能代表真实精度** ✗ |

### 4.4 实机为什么不一样

**实机上相机是"直接看桶"的** —— 它测的是"桶相对飞机"的真实几何 ⇒
环路收敛的是**真实相对几何** ⇒ **精度由释放残差决定**（我们测到的中位 1.85 cm）✓

📄 完整推导：[`../reports/k_accuracy_three_lenses_20261013.md`](../技术文档/专题报告/k_accuracy_three_lenses_20261013.md)

### 4.5 我们能改 EKF 吗

**部分可以**（`EKF2_*` 参数），但要谨慎：

| 参数 | 本机值 | 作用 |
|---|---|---|
| `EKF2_HGT_REF` | 0 | 高度基准源（0 = 气压计）|
| `EKF2_MAG_TYPE` | 5 | 磁罗盘使用模式 |
| `EKF2_GPS_CTRL` | 15 | GPS 参与哪些估计 |
| `EKF2_GPS_P_NOISE` / `_V_NOISE` | 0.5 / 0.3 | GPS 位置/速度噪声 |
| `EKF2_ABL_LIM` | 0.4 | 加速度偏置学习上限 |

> 【经验/建议】**不要为了"让仿真分数好看"去调 EKF 参数** ✗ ——
> 那是**仿真自身的问题**，调参数只会掩盖它。正确的做法是**认清口径**（见 4.3）✓

## 五、OFFBOARD 模式

### 5.1 是什么

PX4 的一种模式：**由外部节点直接给设定点**，飞控只负责"把飞机稳到那个设定点"。

|
|
| 我们的节点发的 | PX4 做的 |
|---|---|
| `/fmu/in/offboard_control_mode` | 声明"我要用哪些字段（位置？速度？姿态？）" |
| `/fmu/in/trajectory_setpoint` | 具体的设定点（每秒 20 次）|
| `/fmu/in/manual_control_input` | AUX5 舵机 PWM（每秒 200 次）|

### 5.2 三个必须知道的规则

| 规则 | 违反的后果 |
|---|---|
| **① 必须先持续发设定点（>2 Hz）才能切进 OFFBOARD** | 切不进去 |
| **② 切进去之后必须一直发** | 断了 ⇒ `COM_OF_LOSS_T = 10 s` 后 failsafe |
| **③ 节点要先于 PX4（或同时）启动** | 晚了就永远进不去（failsafe 已触发 AUTO_LAND）✗ |

**【经验/建议】** 这是实机最常卡住的地方：
"节点起来了，但飞机不动" ⇒ 先查**是不是 OFFBOARD 没进去**，
再查**设定点有没有在发** ✓

## 六、起飞前必查【经验/建议】

这些**每一条都对应一次真实事故或异常**：

| 检查项 | 为什么 |
|---|---|
| **QNH / `EKF2_HGT_REF`** | 【实测数据】有一趟 `Takeoff ref z=353.03`（高度基准偏 **~344 m**）⇒ **在地面就中止了** ✗ |
| **磁罗盘校准** | 有 `Strong magnetic interference` 的先例 |
| **电池电压 / 峰值电流 / 供电线** | 【实测数据】2026-09-30 **主供电线烧断导致坠机**；那趟起飞峰值电流 72.1 A（历史 40~57 A）|
| **EKF 状态无红字** | EKF 没收敛 ⇒ 位置估计不可信 ⇒ 什么都别飞 |
| **GPS/RTK 定位质量** | 影响 EKF 收敛 |
| **AUX5 舵机行程**（拆桨测）| 确认 2000 µs 真能放下载荷 |
| **数传链路** | 出问题要能接管 |

## 八、术语表

| 术语 | 意思 |
|---|---|
| **EKF** | 扩展卡尔曼滤波（飞控的位置估计器）|
| **OFFBOARD** | PX4 的外部控制模式 |
| **setpoint（设定点）** | 我们下发的"目标位置/速度" |
| **QNH** | 海平面气压修正值（影响高度基准）|
| **ARM / 解锁** | 让电机可以转 |
| **failsafe** | 失效保护（出问题时飞控自己采取的动作）|
| **RTK** | 实时动态差分 GPS（厘米级定位）|
| **`pxh`** | PX4 的命令行 shell |
| **ULog** | PX4 的飞行日志格式 |
