## 一、日志分三种，别混

| 类型 | 谁产生 | 内容 | 在哪 |
|---|---|---|---|
| **节点日志** | 机载节点 stdout | 状态流转、伺服明细、**释放行** | `~/fly/log/k_<时间戳>.log`（`k.sh` 自动落盘）|
| **飞控日志（ULog）** | PX4 自己 | 50 Hz 姿态/位置/速度/电机/EKF | QGC 下载，`.ulg` |
| **仿真产物** | `test_k.sh` | mission / detector / judge / summary | `runs/k_<seed>_<时间戳>/` |

**【经验/建议】两者必须配合看**：
- 节点日志告诉你"**节点认为发生了什么**"
- ULog 告诉你"**飞机实际做了什么**"
- 很多结论只有**对齐两者**才能得出 ✓

**【实测数据】** 举个真实例子：2026-09-23 两发都没中，
把节点日志的"等效地面误差"与 ULog 的"飞机 vs 自己设定点"逐点对齐后得到
**corr = 0.90 / 0.95、中位比值 1.01 / 1.10** ⇒
**相机反投影是准的，误差 100% 来自"飞机没停在桶上方"** ✓
这个结论**单看任何一份日志都得不出来**。

## 二、节点日志逐行导读

跑一轮仿真后，打开 `runs/k_33_*/mission.log`，你会看到这些行：

### 2.1 状态流转

```
[STEP] TAKEOFF
[STEP] STABILIZE
[STEP] FORWARD
...
```
**【源码事实】** 状态名与 `k.py` 里 `STEP_NAME` 一一对应（13 个状态）。

### 2.2 粗对准

```
[K-ALIGN] ...
```
**看什么**：粗对准到位时的 xy 误差。
**【实测数据】** 11 轮统计：xy 中位 **2.15 cm**（门限 15 cm）—— 说明粗对准很轻松 ✓

### 2.3 DROP 段的逐拍日志

```
[K-SERVO] t=... 残差=...cm 门限=...cm win=... ...
```
| 字段 | 含义 |
|---|---|
| `t` | 进 DROP 段后的秒数 |
| **`残差`** | 瞄准点与桶估计的偏差 —— **判据用的量** |
| `门限` | 当前的容差（**3 cm**；等待超 `K_WINDOW_S=3.0 s` 后会放宽到 8 cm）|
| `win` | ⚠️ **见下面的警告** |

### 2.4 ★ 释放行（最重要的一行）

```
>>> DROP #0! 残差=2.1cm<=3cm 保持2.00s 触发方式=达标即投 ...
```

| 字段 | 含义 |
|---|---|
| `DROP #N!` | 第几投。⚠️ **`>>> DROP #N!` 是 0-based**，而 `进入 DROP #N` 是 1-based —— 这是已有的不一致，别自己 `+1` ✗ |
| `残差` | 释放那一瞬的偏差 |
| **`触发方式`** | **达标即投** / **释放面强制投** / **必投兜底** |

## 三、⚠️⚠️ 三个必须避开的坑

### 坑 1：判"能否满足 3cm/2.0s"**不能看 `win=`** ✗

`win=` 是"**到达后已经等待了多久**"，不是那个"3 cm 保持 2.0 s"的稳定窗 ✗
（等待超过 `K_WINDOW_S = 3.0 s` 后容差会**放宽** `K_WINDOW_RELAX_M = 0.08`）

⇒ **判定要看 `触发方式=`**（节点自己报的）✓

### 坑 2：**不要用残差序列重建判据** ✗

日志是**每 0.5 s 打一行**（`K_LOG_EVERY = 0.5`）。
如果释放很快，**那 0.5 s 内一行都不打** ⇒
用残差序列重建会得到"样本 0 个 = 不满足" ⇒ **误判** ✗
（实际那是**最理想的情况**：立刻达标立刻投）

### 坑 3：`进入 DROP #N` 与 `>>> DROP #N!` 编号基准不同

前者 1-based，后者 0-based ⇒ 显示时别再加 1 ✗

## 四、ULog 怎么读

| 工具 | 用途 |
|---|---|
| **pyulog**（Python 库）| 脚本里读 `.ulg`（我们所有分析脚本都用它）|
| **PlotJuggler** | 图形化看曲线、对比多条 |
| **ULogViewer** | 第三方查看器（也在外置固态盘上）|
| QGC | 内置的日志分析 |

**【源码事实】** 我们分析 ULog 常用的话题：

| ULog 话题 | 用途 |
|---|---|
| `vehicle_local_position` | 飞机自报位置/速度（EKF）|
| `vehicle_local_position_setpoint` | 我们发的设定点 ⇒ **可复原整条控制链** |
| `vehicle_attitude` | 姿态（pitch/roll）|
| `actuator_outputs` | **PWM 输出** ⇒ 验证舵机脉冲 |
| `vehicle_torque_setpoint` | 力矩 ⇒ **反推载荷摆动** |
| `battery_status` | 电压/电流 ⇒ 供电问题排查 |

**【源码事实】** 库里有真实的 `.ulg`（在带日期的目录里，如 `9.24/`、`10.6/`），
和一批现成的分析脚本（`scripts/analyze_*.py`）。

## 五、★ 误差怎么归因（本章的核心）

### 5.1 误差分解公式

```
落点距真桶心  =  释放残差   ⊕   桶估计误差
              （我们可控）      （参照系的误差）
```

**【实测数据】** 22 投统计：

| 项 | 中位 | 最坏 |
|---|---|---|
| **释放残差** | **1.85 cm** | **2.90 cm** |
| 桶估计误差 | 2.50 cm | 6.11 cm |
| 合计（落点）| 3.34 cm | 8.31 cm |

### 5.2 桶估计误差是什么、为什么它这么重要

**桶估计** = 飞机位置 + 像素偏移 × 高度 / FX
⇒ 如果**视觉是准的**，那桶估计误差就 **≈ 飞机位置（EKF）的误差** ✓

**【实测数据】证明**（某个时刻）：
| 量 | 值 |
|---|---|
| EKF 位置距真值 | **2.1 cm** |
| 像素偏差 2 px 换算的地面距离 | **2.1 cm** |
| ⇒ 两者一致 | **说明视觉是准的，误差在 EKF** ✓ |

**【实测数据】而释放瞬间的 EKF 误差**：**8.3 cm** ⇒ 这才是脱靶的主因 ✗

### 5.3 三个口径：谁能信、谁不能

| 口径 | 怎么读 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| **EKF 口径**（默认裁判）| `/drop/impact_rel` | 环路在 EKF 帧内是否自洽 | **真实精度** ✗ |
| **真值口径**（`GT_JUDGE=1`）| `/drop/impact_gt` | SITL 里的真实几何 | 也被 SITL 的 EKF 偏差主导 ✗ |
| **释放残差** ★ | 释放行的 `残差=` | **环路真正在控的量** → **唯一能预测实机精度** ✓ |

## 六、一次完整的复盘流程

### 第 1 步：跑分析器

```bash
# 仿真日志
python3 scripts/analyze_k_flight_20261013.py runs/k_33_<ts>/mission.log

# 实机日志 + 飞控日志（能看悬停漂移、vxy 静定占比）
python3 scripts/analyze_k_flight_20261013.py ~/fly/log/k_<ts>.log --ulog <x.ulg>
```

**它会输出**：每投的粗对准、释放行、**触发方式**、残差统计、最好的一刻，
最后给出**结论**：`能满足 3cm/2.0s 的投放 n/N`，以及一棵决策树。

### 第 2 步：看决策树怎么走

| 结论 | 含义 | 下一步 |
|---|---|---|
| ✅ 全部"达标即投" | 判据够用 | 不用改，去标定补偿 |
| ⚠ 部分达标 | 分两类：残差**没进过门限**（稳态精度）/ 进过但**保持不住**（飞机停不下来）| 看 ULog 的静定占比 |
| ✗ 全是兜底 | 判据偏紧 | ①归因 ②若是摆动就延长稳定等待/降下降末速 ③若地板就是高，走"释放面强制投 + 挑残差最小的一刻" |

### 第 3 步：批次汇总

```bash
python3 scripts/bench_k_report.py      # 汇总 runs/ 下所有当前代码的轮次
```

**输出**：分数分布、误差分解、每轮明细。

## 七、动手练习

1. **读一轮仿真日志**：跑 `bash scripts/test_k.sh`，然后在 `mission.log` 里
   找出所有 `>>> DROP` 行，把每个字段解释一遍
2. **亲手验证坑 1**：在同一份日志里找到 `win=` 字段，想想如果拿它当判据会得出什么**错误结论**
3. **对比两个口径**：
   ```bash
   bash scripts/test_k.sh            # EKF 口径
   GT_JUDGE=1 bash scripts/test_k.sh # 真值口径
   ```
   对比两次 `summary.json` 的 `total_score`，**差多少？为什么？**
4. **算一次误差分解**：拿一轮的释放残差和落点，看看 `落点 − 残差 ≈ 桶估计误差` 成不成立
5. **读一份真实 ULog**：从 `9.24/` 里挑一个 `.ulg`，用 pyulog 列出它有哪些话题

## 八、术语表

| 术语 | 意思 |
|---|---|
| **ULog** | PX4 的飞行日志格式 |
| **`触发方式`** ★ | 释放行里"这一投是怎么投出去的"（达标即投 / 强制投 / 兜底）|
| **`win`** | "到达后已等待时长"（**不是**稳定窗）|
| **释放残差** ★ | 环路真正在控的量 |
| **桶估计误差** | 桶估计与真值之差（≈ EKF 误差）|
| **静定占比** | 飞机速度小于某阈值的采样占比（衡量"停得稳不稳"）|
| **`dev`** | 历史版本用的诊断量：释放瞬间的"参照漂移" |
