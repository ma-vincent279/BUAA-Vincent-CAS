## 一、为什么飞行任务要用状态机

一个自主飞行任务本质上是：**一串有先后顺序、各自可能失败、需要超时保护的动作**。

```
起飞 → 飞过去 → 找目标 → 对准 → 投 → 返航 → 降落
```

每一段都可能出问题：找不到目标怎么办？对不准怎么办？超时了怎么办？
**状态机**就是把这些"如果…就…"组织清楚的标准做法。

| 概念 | 含义 | 本项目的例子 |
|---|---|---|
| **状态（State）** | 当前在做什么 | `FORWARD`（正在前飞）|
| **事件（Event）** | 触发变化的条件 | "到了投放区" |
| **转移（Transition）** | 从一个状态到另一个 | `FORWARD → HOVER_SEARCH` |
| **超时（Timeout）** | 状态待太久 | 每个状态都有 |
| **兜底（Fallback）** | 出问题时的安全动作 | 找不到目标 → 去侦察区 → 返航 |

## 二、本项目完整状态机【源码事实】

状态名与顺序**逐字取自 `k.py` 的 `STEP_NAME`**：

```
TAKEOFF → STABILIZE → FORWARD → HOVER_SEARCH → TRACK → POSITION_REFINE
        → PRE_SERVO → VISUAL_SERVO → DROP → CLIMB
        → （对第 2 个桶重复 TRACK … DROP → CLIMB）
        → SCOUT → RETURN → LAND
```

**共 13 个状态**。逐个讲：

| 状态 | 干什么 | 退出条件 |
|---|---|---|
| **TAKEOFF** | 解锁 → 切 OFFBOARD → 竖直爬到巡航高度（**3.0 m**）| 到达高度 |
| **STABILIZE** | 原地悬停稳姿态、锁定航向与 home | 稳定一段时间 |
| **FORWARD** | 沿锁定航向直飞到投放区（**`FORWARD_DIST = 32.5 m`**）| 到达距离 |
| **HOVER_SEARCH** | 停下、等检测稳定，**选桶**（按直径升序取最小两个）| 选定目标 |
| **TRACK** | 一边飞一边用视觉跟住目标桶 | 距离够近 / 超时 |
| **POSITION_REFINE** | 精修瞄准点（多次检测求平均，抑制单帧噪声）| 修正量收敛 |
| **PRE_SERVO** | 边下降边持续修正，把桶保持在画面中心附近 | 到达投放高度附近 |
| **VISUAL_SERVO** | 低速闭环：用像素偏差微调位置 | 残差够小 / 超时 |
| **DROP** ★ | **机体坐标系闭环 + 释放判据**（下面详讲）| **投出去** |
| **CLIMB** | 爬升离开，准备投第二个桶 | 离开投放区 |
| **SCOUT** | 飞到侦察区悬停 | 时间到 |
| **RETURN** | 返航到 home 上方，判稳 | 稳定 |
| **LAND** | PX4 自主降落 | 落地 |

> 💡 **两个桶投两次**：`TRACK → … → DROP → CLIMB` 这一组会**走两遍**，
> 每投一个桶重新选一次目标 ✓

## 三、★ DROP 段：什么时候投（全项目最关键的一段）

### 3.1 目标

**把"投放口"挪到"桶口正上方"，然后投。**
难点是飞机永远在漂移 ⇒ 需要一个**可执行、可复现**的判据。

### 3.2 逐拍做什么【源码事实】

每个控制周期（20 Hz）做三件事：

```
① 算残差:   err = rim_body − 释放口偏置
              ↑ 桶在机体坐标系下的偏移   ↑ 释放口相对相机光轴的已知偏移
                                          （当前补偿归零 ⇒ 就是 0）

② 变世界系目标:  目标 = 飞机位置 + R(航向) · err
                 （把"机体坐标系下的偏移"转到世界坐标）

③ 限速后下发:  把目标的变化速度限制在 K_VMAX_DROP = 0.2 m/s
                ⇒ 避免设定点跳变导致飞机追着一个跳动的点飞
```

**为什么要在机体坐标系算偏差？**（★ 重要）
我们关心的是"**桶相对飞机在哪**"，不是"桶在世界哪里"。
在机体坐标系算 ⇒ 对飞控位置的**绝对漂移免疫** ✓
（飞控以为自己偏了 8 cm 也好，只要"桶相对我"是准的，闭环就成立 ✓）

### 3.3 释放判据：三级保底【源码事实】

| 级 | 条件 | 动作 |
|---|---|---|
| **① 达标即投** | 残差 ≤ **3 cm** 保持 **2.0 s** | **立刻投**（最优）|
| **② 释放面强制投** | 到达释放面后，再等 2.0 s 仍不达标 | 强制投 |
| **③ 必投兜底** | 进 DROP 段 **12 s** | 无论如何投 |

**它们对应的代码常量**：

| 常量 | 值 | 含义 |
|---|---|---|
| `K_RELEASE_MIN_M` | **0.03** | 容差下限 3 cm（与复现对象一致）|
| `K_RELEASE_CONFIRM` | **2.00** | 稳定窗 2.0 s |
| `K_DEADLINE_S` | **12.0** | 必投兜底 |
| `K_WINDOW_S` | **3.0** | 等待超过这个时间，容差**放宽** `K_WINDOW_RELAX_M = 0.08` |

> **【经验/建议】为什么要三级？**
> 只有一级（3 cm/2.0 s）时，如果实机永远达不到这个精度 ⇒ **永远不投 ⇒ 比赛 0 分** ✗
> 三级的设计哲学是：**好就早投，不好也一定要投** ✓
> 【实测数据】仿真的 22 投**全部由第①级释放**，零兜底 ✓

### 3.4 两个"门"（防止自己骗自己）

| 门 | 常量 | 作用 |
|---|---|---|
| **残差新鲜度门** | `K_RESID_MAX_AGE = 0.15 s` | 只有**新鲜**的残差才参与判据 —— 防止用"过期的旧帧"误判为达标 ✗ |
| **直径身份门** | `K_DIA_IDENTITY_TOL = 0.03` | 只采信"反推直径与目标一致"的框 —— 防止串到隔壁桶 ✗ |

## 四、其它几个关键设计

### 4.1 两段对准：粗 → 细（D34）【源码事实】

| 段 | 高度 | 到位门 | 稳定要求 |
|---|---|---|---|
| **粗对准** | 约 2.0 m | `K_COARSE_ERR_M = 0.15 m`（15 cm）+ `|Δz| ≤ 0.15 m` | `K_COARSE_STABLE_S = 0.80 s` |
| **细对准** | 约 0.8 m | `K_FINE_ERR_M = 0.08 m`（8 cm）| `K_FINE_STABLE_S = 0.30 s` |

**为什么要分两段**：一上来就要求 3 cm，飞机可能**永远等不到** ⇒ 会一路漂到超时 ✗
先粗（15 cm）把飞机带到桶附近，再细（8 cm）修 —— 这样每一段的目标都是**够得着**的 ✓

（两段各有自己的超时兜底：粗 `K_COARSE_MAX_S = 6.0 s`，细 `K_FINE_MAX_S = 4.0 s`）

### 4.2 FORWARD 起步斜坡（D35）【源码事实】

`K_FWD_RAMPIN_M = 3.0` —— 起步时**速度从小到大渐变**，而不是一上来就全速。

**【实测数据】** 加斜坡前：前飞时俯仰**峰峰 10.7°**、横滚峰峰 4.10°（肉眼可见的"晃"）；
加斜坡后：俯仰峰峰 **2.60°**、横滚峰峰 **0.20°** ✓
（稳态巡航本身很干净，0.04~0.51° RMS —— **晃的根源就是起步/刹车那一下**）

### 4.3 积分项为什么关掉【源码事实】

`K_AIM_KI = 0.00` —— 把瞄准点的**积分项关闭**，只保留代码路径（`K_AIM_BIAS_MAX = 0.40` 上限还在）。

**为什么**：
- 积分项是为了消除稳态误差，但**在飞机持续漂移的场景下**，积分会累积成一个"偏置",
  一旦飞机漂到别处，这个偏置会把它**拽回去** ⇒ 反而更差 ✗
- 而且**复现对象没有这个积分** ⇒ 我们对齐他们 ✓

> 【经验/建议】这条是"盲目照搬自己以前的调参"的反例：
> 我们的历史版本 `i` 里积分是开的，`k` 里关掉 —— **因为它解决的不是这里的问题**。

### 4.4 追踪器：多个桶怎么关联【源码事实】

画面里可能同时有几个桶，追踪器负责"这一帧的框 = 上一帧的哪个桶"：

| 机制 | 作用 |
|---|---|
| **一对一贪心匹配** | 每个框最多配一个已有目标，避免"多个框抢一个桶" |
| **时间确认** | 新目标要连续出现一段时间才被"确认"（防瞬时误检）|
| **同帧去重** | 同一帧里重叠的框只保留一个 |
| **冻结只认已确认目标** | 老的 `i` 版本吃过亏：用了刚建 1.1 s 未确认的追踪器 |

## 五、坐标变换速查

```
                 ┌───────────────┐
   像素 (u,v) ──► │camera_pixel_  │ ──► 机体坐标系下的 (前, 右)/H
                 │to_level()     │     (已去掉 pitch/roll)
                 └───────────────┘
                          │
                          ▼  × H  得到米
                    机体偏移 (前, 右)
                          │
        _body_to_ned(前, 右) ──► 世界 NED 偏移 (北, 东)
                          │
                          ▼  + 飞机位置
                    世界系目标 (北, 东)
                          │
        _pub_pos()  + home ──► 发给 PX4 的绝对 NED
```

**容易搞混的两点**：
1. **NED 的 z 是"向下"** ⇒ 在天上时 `z` 是**负数**；高度用 `home_z − z` 算
2. **发送前要加 `home`**：我们内部用"相对起飞点"的坐标，发给 PX4 时再转成绝对（因为 PX4 的 NED 原点每次上电都不同）✓

## 六、超时与兜底的哲学【经验/建议】

这个项目的状态机里**每个状态都有超时**，而且超时后**绝不原地卡死**：

| 情况 | 兜底动作 |
|---|---|
| 搜不到桶 | 去侦察区 → 返航（不无限找）|
| 对不准 | 两级门 + 12 s 必投 |
| 追踪器丢了 | 原地悬停修正高度，超时后盲降到投放高度 |
| 任何状态卡住 | `STEP_TIMEOUT = 120 s` 全局保护 |
| 任务结束 | 自动退出 + 收尾清理 |

**核心原则**：**宁可投得不准，也一定要把流程走完** ——
比赛里"卡死什么都不做"是最差的结果 ✗

## 八、术语表

| 术语 | 意思 |
|---|---|
| **状态机 / FSM** | 有限状态机（Finite State Machine）|
| **`STEP_*`** | 本项目的状态常量（`STEP_DROP` 等）|
| **残差（residual）** | 瞄准点与桶估计的偏差 —— **判据用的量** |
| **机体坐标系** | x=前, y=右, z=下（相对飞机）|
| **限速** | 限制设定点每拍的变化量，避免设定点跳变 |
| **释放面** | 下降到某高度后的"强制投弹线" |
| **兜底（fallback）** | 出问题时的保命路径 |
