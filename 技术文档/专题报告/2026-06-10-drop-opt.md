# 项目报告 (2026-06-10 投放精度优化)

### 项目目标

在 PX4 SITL Gazebo 仿真环境中，针对单桶（NED y≈10）场景，通过 PID 视觉伺服 + 参数自动迭代，将载荷投放精度优化至最高分。计分规则：d≤0.05→10 | 0.05<d≤0.15→8 | 0.15<d≤0.30→6 | 0.30<d≤0.50→4 | 0.50<d≤0.75→2 | 0.75<d≤1.00→1 | >1.00→0。飞行高度 ≤ 3m。

### 系统架构

```
drop_opt.world (Gazebo)
  └─ target_bucket (红桶, Gazebo 11.01, 0.98 → NED x≈0, y≈10)

bucket_vision_detector ──→ /bucket/detection (ROI, 单桶 Ground Truth 投影)
payload_dropper         ──→ /spawn_entity (自由落体圆柱体)
drop_opt_mission        ──→ /fmu/in/trajectory_setpoint (速度/位置)
  │  9 状态机, PID 像素伺服, 载荷偏移补偿, 零速保持
  ↓
drop_opt_judge ──→ /model_states 获取落点
     细化计分 10/8/6/4/2/1/0
```

### 状态机设计

```
TAKEOFF(爬升至3.0m)
  → FORWARD(飞往桶附近 NED y=10, 纯东方向)
  → SEARCH(0.5m/s 前飞搜索)
  → TRACK(PID+高度锁定, err<40px 稳定5s → DESCEND)
  → DESCEND(PID水平锁定+0.25m/s下降至1.0m, 载荷偏移补偿)
  → HOVER(PID低空收敛, err<25px 稳定5s, 载荷偏移补偿)
  → DROP(PID零速保持+载荷偏移补偿, 稳定后投弹+返航)
  → RETURN(飞回home巡航高度)
  → LAND(降高至home_z, 高度回退双保险disarm)
```

### 优化迭代过程

#### 迭代 1-3：基准线确立

- 初始参数：KP=0.004, DROP=2.0m, DESC_SPD=0.5m/s, HOVER_PX=20, STAB=2s
- 逐步降低投放高度（2.0→1.8→1.5m）、减慢下降速度（0.5→0.35→0.3m/s）
- 发现 HOVER_PX=15 在 1.8m 低空过于严格，放宽至 25px
- 最佳基准：迭代 3 — KP=0.005, DROP=1.5m → **0.2337m (6分)**
- TRACK 阶段 PID 收敛极快：304px→10px 仅 5 秒

#### 迭代 4-6：载荷偏移补偿探索

- 发现载荷 `payload_l` 在机身坐标系左侧 0.13m（来自 `payload_dropper.py` BODY_OFFSETS），导致落点系统性偏向桶北侧
- 引入 `PAYLOAD_OFFSET_BODY_Y` 参数，通过像素偏移使视觉伺服收敛到补偿位置
- 迭代 4（正偏移 +0.13）：0.2107m (6分) — 有效但超调
- 迭代 6（负偏移 -0.10）：0.2844m — 方向错误，更差
- 确认体轴约定 `body +y = 左`，`payload_l` 在左侧 = 北偏，正像素偏移 = 飞机北移补偿 ✓

#### 迭代 7-8：零速保持 + 更低投放

- 在 DROP 状态加入零速保持阶段：进入 DROP 后先抑制水平速度 < 0.05m/s，再释放载荷
- 降低投放高度至 1.0m，延长稳定时间至 5s
- 关掉载荷偏移补偿，纯视觉伺服对准
- 迭代 8 spawn 分析：载荷生成点距桶约 0.10m（8 分范围），但裁判因环境变量遗漏未记录

### 关键技术发现

#### 1. 载荷侧向偏移是精度瓶颈

`payload_l` 在 `payload_dropper.py` 中定义为 `BODY_OFFSETS['payload_l'] = (0, 0.13, -2.0)`。在体轴约定 body +y = 左 下，此载荷位于机身左侧。当 heading≈90°（正东）时，左侧 = 正北。视觉伺服将飞机对准桶中心后，载荷自动落在桶北侧 0.13m。

即便飞机位置完美，落点距离也不少于 0.13m。加上残余水平速度（~0.05-0.10m/s），实际落点偏差约 0.15-0.25m。

#### 2. 像素偏移补偿方向确认

`_body_to_ned` 的转换公式：`vx = v_fwd*cos_h - v_lat*sin_h`。体轴 body +y = 左。正像素偏移 → `ex_effective = cx - center - offset`（更负）→ v_lat < 0（body-left = 北移）。正偏移将飞机推向北方以补偿南偏载荷。迭代 4 的正偏移确实优于无偏移，方向确认。

#### 3. 零速保持比偏移补偿更有效

降低投放高度至 1.0m + 延长稳定时间至 5s + DROP 阶段强制抑制水平速度 < 0.05m/s，比像素偏移补偿更稳定（不会引入 PID 超调）。迭代 8 spawn 分析表明载荷生成点距桶约 0.10m。

#### 4. 环境变量容易遗漏

`PX4_SITL_WORLD` 必须在启动 PX4 时设置，否则 Gazebo 使用默认空世界（无桶模型、无 `libgazebo_ros_state` 插件），导致 `/model_states` 无数据、裁判无法打分。

### 最佳参数组合

```python
DROP_HEIGHT     = 1.0       # 投放高度 (m), 最低
KP_H = 0.006                 # PID Kp, 快速收敛
HOVER_ARRIVE_PX  = 25.0    # HOVER 收敛阈值, 合理宽松
STABILIZE_TIME   = 5.0     # 稳定时间 (s), 确保零速
DESCEND_SPEED    = 0.25    # 下降速度 (m/s), 慢速防漂
PAYLOAD_OFFSET_BODY_Y = 0.0  # 关偏移, 纯视觉伺服
```

### 突破 8 分的下一步方向

1. **修改 payload_dropper 投放中心位置**：将首次投放的 `BODY_OFFSETS` 改为 `(0, 0, -2.0)`，消除 0.13m 系统偏移，预计距离 < 0.10m
2. **按 heading 自适应补偿**：根据实时 heading 计算 payload_l 的 NED 偏移方向，动态调整像素偏移
3. **两次投放取平均**：左右两侧各投一枚，取两枚中最佳成绩

### 已知局限

- 多个 `payload_dropper` 实例共存时，`/drop_payload` 服务会被多次响应，导致一枚以上载荷被同时投放
- 裁判节点依赖 `/model_states` 话题，需确保 `PX4_SITL_WORLD` 正确设置使 `libgazebo_ros_state` 插件加载
- 旧载荷模型在 Gazebo 中持久存在，裁判可能将其误判为当次投放结果（需每次重启 Gazebo 清理）
- PID 收敛到 < 10px 后，残余水平速度仍可能 > 0.05m/s，1.0m 高度投放仅 0.45s 落体时间，速度漂移贡献约 0.02-0.05m 喵~
