## 一、为什么速度也要改

### 1.1 【源码事实】速度通道的公式

```cpp
// src/modules/ekf2/EKF/aid_sources/gnss/gps_control.cpp:316
const float vel_var = sq(math::max(gnss_sample.sacc, _params.ekf2_gps_v_noise, 0.01f));
//                                     ↑ RTK自报速度精度      ↑ 参数        ↑ **硬编码下限** ⚠
```

⚠️ **注意那个 `0.01f` 是写在代码里的硬下限** ⇒
**`EKF2_GPS_V_NOISE` 设到 0.01 以下没有任何效果** ✗ ⇒ **0.01 就是有效最小值** ✓

### 1.2 代入实测值

| | 值 |
|---|---|
| RTK 自报速度精度 `sacc` | **0.0009 m/s** ✓✓ |
| 改前 `EKF2_GPS_V_NOISE` | 0.3 ✗ ⇒ **大了 333 倍** ✗✗ |
| **改后生效值** | **`max(0.0009, 0.01, 0.01) = 0.01`** ✓ |

⇒ 改后由**代码下限**决定（而不是被参数过度放大 ✓）

### 1.3 为什么速度重要

**速度偏差会通过积分直接变成位置漂移** ✗ ⇒ 这正是"位置飘"的另一条来源 ✓

这也解释了 SITL 判决实验里"**只改 `P_NOISE` 改善但没到最好**"这一现象 ✓
（那组最好的是 `P_NOISE=0.02` + **`V_NOISE=0.05`** + `TAU_POS=0.1` ✓）

## 三、查过的第三条通道：GNSS 双天线航向（**改不了，但影响也小**）

### 3.1 发现

```cpp
// src/modules/ekf2/EKF/aid_sources/gnss/gnss_yaw_control.cpp:139
const float R_YAW = sq(fmaxf(yaw_acc, _params.gnss_heading_noise));
//                                 ↑ RTK自报航向精度   ↑ **硬编码默认 0.1 rad** ⚠
```

**【源码事实】** `gnss_heading_noise = 0.1f`（rad）**硬编码在 `common.h:389`** ✗
⇒ **没有对应的 PX4 参数** ✗ ⇒ **改不了**（要改得动源码 + 重新编译 ✗）

**实飞日志印证** ✓：
| 量 | 值 |
|---|---|
| `estimator_aid_src_gnss_yaw.observation_variance` | **恒为 0.01** ⇒ 噪声 = **0.1 rad = 5.73°** ✗ |
| `fused` | **1.0**（一直在融合 ✓）|
| `innovation_rejected` | **0** ✓ |
| `test_ratio` 最大 | **0.027** ✓（极小）|

⇒ **EKF 把双天线航向按"5.73° 精度"加权** ✗ —— 而实际 innovation 极小（max 2.5°）⇒ **实际精度好得多** ✗

### 3.2 ★ 但**对我们的投放影响很小** ✓（机体坐标系闭环的价值）

我们的闭环是：

```
目标 = 飞机位置 + R(航向) · err_body          ← err_body 是"桶在机体坐标系下的偏移"
```

⇒ 环路把 **`err_body` 驱动到 0** ✓
⇒ 航向误差 δ 会让**世界系目标点**转一个 δ ✗ —— 但飞机是**追着这个目标点走**的 ✓
⇒ **收敛点仍然满足 `err_body = 0`** ✓✓ ⇒ **航向误差不进入稳态残差** ✓✓

**定量**：侧向目标偏移 1.5 m、δ=5.73° ⇒ 世界系目标偏 **15.0 cm** ✗
⇒ 但**这个偏移只改变飞机站位**，不改变 `err_body` ⇒ **落点不受影响** ✓

> 💡 **这正是"在机体坐标系算偏差"这个设计的价值** ✓✓
> 它对 **EKF 的绝对位置漂移免疫**，同样也对 **航向误差免疫** ✓

⚠️ **会受影响的是**：`FORWARD` 段直飞与侦察航路的**世界系**航向精度
（5° 误差 × 32 m ≈ 2.8 m 横向 ✗）—— 但投放区有 5 m 宽 ✓ 且进区后靠**视觉搜索**兜底 ✓
