## 五、🆕 新发现：**速度通道仍然被参数卡着** ✗

```cpp
// gps_control.cpp:316
const float vel_var = sq(math::max(gnss_sample.sacc, _params.ekf2_gps_v_noise, 0.01f));
```

代入：

```
max(0.0009, EKF2_GPS_V_NOISE=0.3, 0.01) = 0.3     ← 参数说了算 ✗
                     ↑ RTK 实际只有 0.0009 m/s ⇒ 大了 **333 倍** ✗✗
```

⇒ **这条通道**（速度）**没有被本次修改覆盖** ✗
⇒ ⇒ 而 **速度偏差会通过积分直接变成位置漂移** ✗ —— 正是"位置飘"的另一条来源 ✓

**这解释了**：为什么 SITL 判决实验里"**只改 `P_NOISE`** 后精度改善但**没到最好**" ✓
（实验里 🥇 最好的一组是 **`P_NOISE=0.02` + `V_NOISE=0.05` + `TAU_POS=0.1`** ✓）

> 📌 建议：**这就是之前说的"阶段 2"** ✓ —— 但按用户要求，**本次只改了 `P_NOISE`** ✓

## 六、回答"为什么还要当地气压"

### ✅ 用户的直觉是对的

**改完之后**：气压计对高度的贡献只有 **0.3%** ✓
⇒ **QNH 设不设，对"高度估计"影响极小** ✓
⇒ **我上一轮把 QNH 的优先级说高了** ✗ —— 那是因为**当时还没算这个权重比** ✓

### ⚠️ 但仍有两个"但是"

| # | 理由 | 定量 |
|---|---|---|
| **①** | **RTK 短暂失锁时，气压计会接管** ✓ | 实飞日志里 `check_fail_gps_fix` = **0.43%** ✗（RTK 会有短暂降级）<br>⇒ 接管瞬间若 QNH 差 40 hPa（≈**340 m** ✗）⇒ EKF 会看到巨大的高度创新 ✗<br>⇒ 会被 `hgt_test_ratio` **拒收**（日志实测最大 0.75，门限 1.0 ✓）⇒ **有保险** ✓ 但会有扰动 ⚠ |
| **②** | **成本为零** ✓ | 现场看一眼气压/气象站就有了 ✓ |

### ⇒ 结论

| 项 | 优先级 |
|---|---|
| **`SENS_BARO_QNH`** | **低** ✓ —— **不必现在纠结** ✓ 顺手设了更保险 ✓ 不设影响也很小 ✓ |
| **`EKF2_GPS_V_NOISE`（阶段 2）** | **中-高** ⚠ —— 它**仍然在拖后腿**（333 倍 ✗），且**直接造成位置漂移** ✓ |
