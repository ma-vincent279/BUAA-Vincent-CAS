## 事故 1 · 🔴 **`EKF2_GPS_P_NOISE` 与 RTK 严重不匹配 ⇒ 飞机缓慢漂移**（★ 本模块最重要的一条）

### 现象

- 实飞时飞机**停不稳**，位置**缓慢漂移**（水平游走 0.09~0.18 m/s）
- **12 份实飞日志的 `estimator_status.pos_horiz_accuracy` 都是 0.227~0.239 m**，
  几乎一模一样 ⇒ 说明这是一个**参数驱动的地板，不是随机噪声** ✗

### 排查（12 份 `.ulg` 实测）

先排除输入端：

| 项 | 结果 | 结论 |
|---|---|---|
| RTK（同型号）| `fix_type = **RTK fixed**`、`eph = **0.000 m**`、卫星 34~47、`cs_gnss_pos` **100%** | ✅ **输入是完美的** |
| IMU 裁剪 | `accel/gyro clipping = 0`（12/12）| ✅ 无饱和 |
| 加速度模长 | 9.85~10.07 m/s² | ✅ 正常 |

⇒ **输入端没问题** ⇒ 问题在**参数** ✓

### 根因

```
EKF2_GPS_P_NOISE = 0.5      ← PX4 原文: "Measurement noise for GNSS position"
```

**0.5 m 是 PX4 的默认值**（给普通 GPS 用的）✓
**但我们的 RTK 精度是 `0.000 m`** ✗

⇒ 把精度 0 的 RTK **当成精度 0.5 m 的普通 GPS 去加权** ⇒
**卡尔曼增益被压小 10~25 倍** ⇒ 位置估计**主要靠惯性递推** ⇒ **缓慢漂移** ✗

⇒ 这正好解释了 `pos_horiz_accuracy = 0.23 m`（= 0.5 m 噪声下的稳态协方差量级）✓

**同批可疑项**：

| 参数 | 值 | 默认 | 问题 |
|---|---|---|---|
| `EKF2_GPS_P_GATE` / `V_GATE` | 7.0 | 5.0 | 放宽了（更容易接受跳变）|
| `EKF2_GPS_CHECK` | **1023** | 2047 | **少了一项检查** ⚠ |
| `EKF2_GPS_DELAY` | **0** | 110 | 手工改过 |

### 判决实验（SITL，探针 3 定点，同一序列）

**【实测数据】** `PX4_PARAMS="EKF2_GPS_P_NOISE=0.02" bash scripts/test_k.sh hover_probe`

| 阶段 | 默认 0.5 | **改后 0.02** | 0.02 + `V_NOISE=0.05` + `TAU_POS=0.1` |
|---|---|---|---|
| HOLD0（起飞点）| 9.6 cm | **4.6 cm**（−52%）| **3.8 cm** |
| HOLD1（投放区）| 26.0 cm | **15.4 cm**（−41%）| **10.1 cm** |
| HOLD2 | 18.2 cm | **8.5 cm** | 8.8 cm |
| 游走 vxy | 0.090 / 0.178 / 0.154 | 0.037 / 0.123 / 0.064 | 0.045 / 0.100 / 0.079 |
| **≤3 cm 最长连续** | 1.35 s | 0.00 s | 0.10 s |
| 达标阶段（≥2.0 s）| 0/4 | 0/3 | 0/3 |

⇒ **保持误差与游走速度都减半**（真收益）✓
⇒ **但 3 cm / 2.0 s 仍然达不到** —— 改后中位降到 8 cm 级，但**抖动还在** ✗

### 处置

| 步骤 | 做什么 |
|---|---|
| ① | **上实机验证** —— 把 `PX4_PARAMS` 里那一行原样搬到板载参数 ✓ |
| ② | 顺序很重要：**先修参数 → 再看判据能不能达到**（不要靠"照抄严格判据"来掩盖参数问题）✗ |
| ③ | 工具：`scripts/analyze_probe_gate_20261012.py`（在探针 CSV 上算 ≤3 cm 占比/最长连续）|

> ⚠️ **注意**：`EKF2_GPS_P_NOISE = 0.5` **不在**"86 项偏离"清单里 ——
> **因为它就是 PX4 默认值** ✓ 我没改它，但它**依然是不匹配的** ✓
> 这条结论**依然成立，且是待做实机实验** ✓

## 事故 2 · 🔴 **`SENS_BARO_QNH` 是默认值 ⇒ 高度基准偏 344 m ⇒ 地面中止**

### 现象

2026-10-07 一趟实飞：`ARM OK` 但**进不了 OFFBOARD**，
日志里 `Takeoff ref z = 353.03` —— **高度基准偏了约 344 m** ✗

### 根因

**`SENS_BARO_QNH = 1013.25`（标准大气压默认值）**，**不是当地 QNH** ✗
⇒ 气压高度解算偏差 ⇒ 整个高度基准错位 ⇒ 起飞参考高度离谱 ⇒ 任务无法开始 ✓

### 处置

**起飞前必查**：

- [ ] QGC 里核对 `SENS_BARO_QNH` 与**当地气压**
- [ ] 核对 `EKF2_HGT_REF`（0 = 气压计 / 1 = GPS）

> **【经验/建议】** 这条已经写进 [`../飞行操作与首飞清单.md`](../飞行操作与首飞清单.md) ✓

## 事故 3 · 🔴 **`SYS_AUTOSTART = 0` ⇒ 没有机型 ⇒ 飞不了**

### 现象

新板子（PX4 FMU V6C）上电后：`ERROR [init] No airframe file found for SYS_AUTOSTART value` ✗

### 根因（参数审计）

| 参数 | 值 | 后果 |
|---|---|---|
| **`SYS_AUTOSTART`** | **0** | **没有机型配置** ⇒ 飞控不知道自己在控什么 |
| `CA_ROTOR_COUNT` | **0** | **没有电机配置** ⇒ **无混控器** |
| `MAV_TYPE` | **0**（GENERIC）| 不是 QUADROTOR |

⇒ 这块板**当时是飞不了的** ✗（参数审计的结论）

### 处置

```bash
# 设机型（X500 V2）
param set SYS_AUTOSTART 4019
# 重启后再做：传感器标定 / 遥控器校准 / 电调协议 / 电源模块标定 / 罗盘
```

## 事故 4 · ⚠️ **`BAT1_V_DIV` / `BAT1_A_PER_V` 是默认值 ⇒ 电压电流读数不可信**

### 现象

电压/电流读数与万用表对不上 ✗

### 根因

| 参数 | 新板值 | 说明 |
|---|---|---|
| `BAT1_V_DIV` | 31（默认）| **未按实际电源模块标定** |
| `BAT1_A_PER_V` | 24（默认）| 同上 |
| `BAT1_CAPACITY` | **−1** | **未设容量** ⇒ 没有电量百分比 |
| `BAT1_N_CELLS` | 0 | 自动识别（真机是 **6**）|

### 后果（★ 这条是有血的）

**【实测数据】** 2026-09-30 那次**主供电线烧断坠机** —— 排查时**必须看电流**
（当时 41.7 A 突然变 0 A）。如果**电流标定不准，这类故障就看不出来** ✗

### 处置

按实际电源模块**重新标定**：

```bash
param set BAT1_V_DIV   <实测分压比>
param set BAT1_A_PER_V <实测每伏安数>
param set BAT1_N_CELLS 6
param set BAT1_CAPACITY <电池容量 mAh>
```

## 事故 5 · ⚠️ **`EKF2_EV_CTRL = 3` ⇒ 开着外部视觉融合，但本机没有 VIO 源**

### 现象（潜在）

真飞控的画像里 `EKF2_EV_CTRL = 3`（默认 0）—— **外部视觉位置融合是开着的** ⚠

### 问题

**本机没有 VIO / 外部视觉源** ⇒ 这个开关**开着没有意义**，
但万一有别的模块往 `/fmu/in/vehicle_visual_odometry` 发东西，
**会被融合进位置估计** ⇒ 污染 ✗

### 处置

**【待验证】** 复核这个参数是否该关（`param set EKF2_EV_CTRL 0`）✓

## 事故 6 · ⚠️ **`RC_MAP_AUX5` 没解除 ⇒ 遥控器和程序抢 AUX5 通道**

### 现象

程序在发投放 PWM，但舵机**不动**或**乱动** ✗

### 根因

**【源码事实】** AUX5 走的是 **RC 输入 → 混控器 → AUX5 引脚** 的路径，
而 **SBUS 接收机也在往这个通道写值**（更新率 ~111 Hz）✗
如果 `RC_MAP_AUX5` 还映射着遥控器通道，**两者会互相覆盖** ✗

### 处置

```bash
param set RC_MAP_AUX5 0        # Unassigned —— 解除遥控器占用, 让 DDS 数据独占
param set PWM_AUX_FUNC5 411    # AUX5 输出配置成舵机
```

> 这也是**为什么程序必须发 200 Hz** —— 要比接收机快才能"盖住"它 ✓

## 事故 7 · ⚠️ **`COM_OF_LOSS_T = 10 s`（默认 1 s）—— 是有意放宽的**

### 说明

真飞控把 **offboard 失联超时从 1 s 放宽到 10 s** ✓

**为什么**：我们的任务节点在**投放段**会做计算密集的事（视觉 + 判据），
万一某一拍卡顿超过 1 s，**飞控就会触发 failsafe 切走** ✗
放宽到 10 s 是**为了让任务能跑完** ✓

> ⚠️ **代价**：真失联时**反应变慢**（10 s 才切 failsafe）✗
> ⇒ 这是**有意的取舍**，换机时**要一起抄过去**（否则任务会莫名中断）✓

## 事故 8 · ⚠️ **`EKF2_HGT_REF` / `EKF2_GPS_CTRL` / `EKF2_MAG_TYPE` 换机时不一致**

| 参数 | 新板 | **真机（正确值）** | 说明 |
|---|---|---|---|
| `EKF2_HGT_REF` | 1（GPS）| **0（气压计）** | 高度基准源 |
| `EKF2_GPS_CTRL` | 7 | **15** | 15 含 **RTK 双天线航向** ✓ |
| `EKF2_MAG_TYPE` | 0（自动）| **5（仅初始化）** | 见下 |
| `EKF2_GPS_P_GATE`/`V_GATE` | 5.0 | **7.0** | 放宽了 |
| `EKF2_GPS_CHECK` | 2047 | **1023** | 少一项检查 |
| `EKF2_GPS_DELAY` | 110 | **0** | 手工改过 |
| `EKF2_MAG_DECL` | 0（自动）| **−6.13°** | 磁偏角**手工写死** |

> **【经验/建议】`EKF2_MAG_TYPE = 5`（仅初始化）是有意的** ——
> 我们的飞机上装了**电机、电调、大电流线**，**飞行中磁罗盘很容易被干扰** ✗
> ⇒ 只用它做初始朝向，之后靠 GPS 航向 + 陀螺递推 ✓
