## 一、参数系统怎么用

### 1.1 参数的存储格式

从实机导出的 `.params` 文件是 **tab 分隔**的：

```
sysid␉compid␉参数名␉值␉类型
1␉1␉BAT1_N_CELLS␉6␉6
```

**用命令行读**（比手翻 1199 行快）：

```bash
# 查一个参数
awk -F'\t' '$3=="BAT1_N_CELLS"{print $4}' 硬件/PX4参数_RTK.params

# 列出所有 EKF2 参数
awk -F'\t' '$3 ~ /^EKF2_/ {print $3, $4}' 硬件/PX4参数_RTK.params
```

### 1.2 三种改参数的方式

| 方式 | 用在哪 | 特点 |
|---|---|---|
| **QGC** | 实机 | 图形界面；**Parameters → Tools → Load from file** 可整包载入 |
| **`pxh` 命令行** | 仿真 / 实机 shell | `param set 名 值` / `param show 名` / `param save` |
| **`PX4_PARAMS=` 环境变量** | **仿真**（`test_k.sh`）| 通过 pxh 的 stdin FIFO 注入，**零污染实验** ✓ |

**【源码事实】** 仿真里的用法：

```bash
PX4_PARAMS="EKF2_GPS_P_NOISE=0.02" bash scripts/test_k.sh hover_probe
```

> ⚠️ **改完必须重启飞控才生效**（有些参数改了要重新初始化模块）✗
> ⚠️ **`param set` 会立刻落盘，没有反悔窗口** ✗ ⇒ 改之前先 `param show` 备份 ✓

## 二、四条规矩（换机/换场地时必看）

### 规矩 1 · **不要把所有"差异"都当成"有意设置"** ✗

手上这块板和真机那块板**型号不同** ⇒ **board defaults 本来就不同**
（如 `COM_CPU_MAX` / `RC_CHAN_CNT` / `PWM_MAIN_*`）
⇒ **换机只抄"有意设置"，不抄板级默认** ✓

### 规矩 2 · **`CAL_*` 绝对不能抄** ✗

画像里的 `CAL_*` 是"**该机最后一次的传感器标定值**"，换机后**必须重新标定** ✗

### 规矩 3 · **画像只用于比对，不要整机回灌** ✗

参数之间**有耦合**（机型 → 混控器 → 电机映射 → 电调协议）。
整包回灌会把目标机上本来就对的东西改错 ✗

### 规矩 4 · 换场地要改的参数

| 参数 | 为什么 |
|---|---|
| `SENS_BARO_QNH` | **当地气压** —— 不设就走了默认 1013.25 ✗（见 [`参数事故记录.md`](参数事故记录.md) 事故 1）|
| `EKF2_MAG_DECL` | 当地**磁偏角** |
| 代码里的 `HEADING_DEG` | 场地航向（部署脚本会自动改）|
| 代码里的 `FORWARD_DIST` | 起降点到投放区的距离 |

## 三、参数全景（我们从 12 份实飞 ULog 重建出的画像）

**【实测数据】** 用 12 趟实飞日志重建真飞控的参数，与 PX4 默认逐项比对：

| 类别 | 项数 |
|---|---|
| 与默认**不同**（配置类）| **86 项** |
| 板级参数（型号差异，**不该抄**）| 267 项 |
| **标定类**（`CAL_*`，**绝对不能抄**）| 131 项 |

> ⚠️ **【源码事实】订正**：早期记录写的是"13 项偏离"✗ —— 那是**手动比对**的结果；
> 后来用 `parameters.json` 全量比对，真实是 **86 项** ✓
> 并且捞出了多项此前未记录的：**自动整定出的 `MC_*` PID 增益**、`FD_ACT_EN=1`、
> `EKF2_GPS_POS_X/Z` 天线偏移等 ✓

完整清单见 [`../专题报告/fc_param_20261014.md`](../专题报告/fc_param_20261014.md) 第八节。
