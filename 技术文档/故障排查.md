按「症状 → 原因 → 处置」组织。每一条都对应一次真实的踩坑。

## 一、仿真侧

| 症状 | 原因 | 处置 |
|---|---|---|
| **飞机起不来 / 0 投 / 挂到超时** | **残留 `gz sim` 进程** ⇒ `Task already running` + `gz_bridge failed to start` | `bash scripts/cleanup_sim.sh` |
| **解锁要 24 s、飞机飞到 39 m** | 残留 **`ros_gz_bridge`** 一直灌 250 Hz 位姿数据，把 OFFBOARD 流**饿死** | 同上（清理脚本**连 ROS 侧一起清**）|

## 二、实机侧

| 症状 | 原因 | 处置 |
|---|---|---|
| 订阅话题**没数据** | 话题名少了 **`_v1`** 后缀 | 改成 `/fmu/out/xxx_v1` |
| **进不了 OFFBOARD** | 节点启动**晚于** PX4 ⇒ 已触发 offboard failsafe | 节点必须在 PX4 **之前/同时**启动，持续发 setpoint >2 Hz |
| `ros2 run` 跑的还是旧代码 | 没 `colcon build`，或 build 了没 `source` | 两步都做 |
| YOLO 崩溃 `_ARRAY_API not found` | NumPy 版本冲突 | 设 `PYTHONPATH` 指向 conda 环境 |
| 摄像头分辨率不生效 | 默认后端无法设 V4L2 分辨率 | `cv2.CAP_V4L2` + MJPG fourcc |
| `Takeoff ref z=353.03`（高度基准偏 ~344 m）| **QNH / `EKF2_HGT_REF` 不对** | 起飞前在 QGC 核对 |
| 飞机不动 / 双链路无响应 | 残留 DDS Agent | 清理残留进程后重启 |

## 三、代码/验收侧

| 症状 | 原因 | 处置 |
|---|---|---|
| 离线验收全过，**真跑一轮却崩** | 验收是静态检查，抓不到运行时错误（例：计数器在 DROP 入口初始化，但回调从起飞就跑）| **改完必须跑一轮真仿真** |

## 四、网络/GitHub 侧

| 症状 | 原因 | 处置 |
|---|---|---|
| `github.com` 打不开、连不上 | 本机走 **Watt Toolkit 加速器**（本地 MITM 代理）| 见下 |
| `SSL certificate problem: unable to get local issuer certificate` | **加速器的自签 CA 没被信任** | 装 CA（见下）|
| 浏览器报证书错 | Chrome 的 NSS 库里该 CA 的信任属性是 `C,,`（只登记不信任）| 改成 `CT,C,C` 并**重启 Chrome** |
| 改 hosts 后全挂了 | hosts 里有**工具管理的区块**（`# Steam++ Start/End`）—— 那是加速器的工作机制 | **一律不要动那些区块** |

**修加速器证书**：

```bash
# ① 系统级（管 curl / git / python）
sudo cp <SteamTools.Certificate.cer 转成的 PEM> /usr/local/share/ca-certificates/steamtools.crt
sudo update-ca-certificates

# ② Chrome 的 NSS 信任
certutil -d sql:$HOME/.pki/nssdb -M -n "SteamTools" -t "CT,C,C"
```

**注意**：`github.com:443` 在本机是**网络层阻断**的，
所有 git 操作必须走 **`ssh.github.com:443`**（配置见 `~/.ssh/config`）。
