一、项目背景
================================================================================

无人机视觉伺服自主投放系统。最终目标: 无人机从起飞点起飞，飞到 12.5m 外、
8m x 5m 矩形区域上空，通过下视摄像头 + YOLOv8 检测 3 个相同红色圆桶，
自主选择 2 个，依次飞到桶正上方 1m 高度，通过 AUX5 舵机投下乒乓球。
乒乓球落点距桶中心越近得分越高 (d <= 0.05m = 10分)。

  起降点                        投放区(8x5m矩形)
  ╳                              ┌──────────────┐
  │                               │ B1  B2  B3   │  ← 3个红桶
  └────────── 12.5m ─────────────→│              │
                                  └──────────────┘
                                  10m         15m
                                  (NED y 坐标)

技术栈:
  - 飞控: PX4 1.17 SITL (Gazebo Classic)
  - 中间件: ROS 2 Humble + XRCE-DDS (MicroXRCEAgent)
  - 语言: Python 3.10
  - 坐标系: NED (北-东-地), PX4 原点=飞机 Gazebo 生成点 (1.01, 0.98, 0.83)
  - 相机: 下视 640x360, 85deg HFOV / 54deg VFOV, FX/FY ~349/353
  - 检测: YOLOv8 sim 模式 (GT 投影白圆 + 噪声背景合成图像)

实机平台: Jetson Orin NX, 5.3kg F450, 15寸桨, YOLOv8 TensorRT, AUX5 舵机

三、final_mission.py 核心架构 (v6)
================================================================================

12 状态机 (940 行 Python):

TAKEOFF → STABILIZE → FORWARD → HOVER_SEARCH → TRACK → POSITION_REFINE
→ APPROACH → VISUAL_SERVO → DROP → CLIMB → (下一桶 TRACK) → RETURN → LAND

详细流程:
  1. TAKEOFF:     竖直爬升到巡航高度 4m
  2. STABILIZE:   悬停 3s 稳姿态，锁定 heading0 (纯东~92deg) + home
  3. FORWARD:     _pub_pos 位置控制飞到矩形中心 NED(0, 12.5)，undershoot 1.2m
  4. HOVER_SEARCH: 中心悬停，一次性识别所有桶 (ROI->NED 估算)
                   几何围栏(NED x∈[-4,4], y∈[10,15]) + 距离门(6m)
                   + 帧间稳定性(NED跳变<1.5m) + 5帧确认
                   v6: 全选围栏内桶 (距离近优先，不再限制2个)
  5. TRACK:        _pub_pos 位置控制飞向锁定坐标，PX4 自动导航刹车
  6. POSITION_REFINE: 悬停 2s，几何身份锁收集 ROI->NED 样本 -> 平均修正
                   修正量 >1.5m 拒绝 (防身份混淆)
  7. APPROACH:     慢速下降 0.2m/s + 位置保持，监控视野内桶数量
                   只剩 1 个桶 -> 隔离成功 -> VISUAL_SERVO
                   15s 超时 -> 强切 VISUAL_SERVO
  8. VISUAL_SERVO: 单目标纯 PID 像素伺服 (无身份歧义)
                   PID -> 速度 -> 位置增量 -> _pub_pos
                   收敛: err<8px 持续 2.5s -> DROP
                   总超时 35s -> 强投
  9. DROP:         继续位置增量伺服 + AUX5 舵机投放 (B1=2000us, B2=1000us)
 10. CLIMB:        三段: 竖直爬升 -> 飞回中心 -> 直接 TRACK 下一桶 (不重搜)
 11. RETURN:       _pub_vel 速度控制飞回 home
 12. LAND:         PX4 自主着陆 MAV_CMD_NAV_LAND，15s 超时强制 disarm

关键设计:
  - 几何身份锁: _cb_detect 遍历所有检测找 NED 最近邻，不用 nearest-center
  - 位置增量控制: PID 输出 -> v*dt -> NED 位置增量 -> _pub_pos
    绕过 PX4 SITL 低速(<0.3m/s)速度跟踪极差的问题
  - PID height_scale: KP/KD *= H/GROUND_NED_Z，低空自动缩小增益防摇晃
  - Yaw 分层: 盲飞阶段 yaw=heading0，视觉伺服阶段 yaw=live heading

--- 问题 A: 几何身份锁阈值太宽 (严重, 低修复成本) ---

现状: GEO_IDENTITY_MAX = 2.5m, POSITION_REFINE_IDENTITY_MAX = 2.0m

  pitch 振荡 +-1.5deg         -> +-13cm
  合计 (RSS)                  -> ~39cm

建议阈值: 1.5m (~3.8 sigma, 小于最小桶间距 2.2m)
修复: 改 2 行代码

--- 问题 B: APPROACH 隔离不可靠 ---

现状: APPROACH 以 0.2m/s 慢速下降等待 FOV 缩小到只剩 1 个桶
      但耗时很长，15s 仅降 3m (4m -> 1m)
      即使降到 H=1m，FOV 水平宽 ~2.9m
      桶间距 2-3m 的情况下，2 个桶可能始终同框
      -> 15s 超时强切 VISUAL_SERVO -> 多目标伺服 -> 身份混淆

可能的改进方向:
  - 利用已知桶坐标主动平移飞机使 1 个桶移出 FOV
  - 先飞到一个桶正上方 (更近的距离门) 再下降
  - 接受多目标伺服但收紧身份锁阈值

--- 问题 C: B2 伺服精度差 (0.56m vs B1 0.25m) ---

v5 测试中 B2 是对 B3 的错误投放 (身份混淆)。v6 H 修复 + 全选桶后
B2 应能被正确纳入目标列表，但第二个桶的 VISUAL_SERVO 时间仍受限:
  - 第一个桶: APPROACH(~7s) + VISUAL_SERVO(~15s) + DROP(~2s) = ~24s
  - CLIMB + 飞回中心 ~10s
  - 第二个桶: TRACK(~5s) + POSITION_REFINE(~2s) + APPROACH(~7s)
    + VISUAL_SERVO(~剩余) + DROP(~2s)
    总耗时 > 60s，MISSION_TIMEOUT=300s 压力不大
    但 VISUAL_SERVO_TIMEOUT=35s 可能需要调大

--- 问题 D: VISUAL_SERVO 位置增量无界漂移 ---

现状: _servo_target 通过 PID -> 速度 -> 位置增量无限累加
      无边界检查，无与原始目标坐标的约束
      长时间伺服或丢检恢复后，_servo_target 可能漂离很远
      此时几何身份锁即使正确匹配，飞机也在错误位置

建议: _servo_target 更新时加软约束 (距 _current_target_ned < 2m)
      或定期回拉

--- 问题 E: 实机验证完全缺失 ---

final_mission 从未在实机上测试过。实机特有挑战:
  - YOLOv8 ~100ms 推理延迟 + 10Hz 节流
  - 5.3kg 重机物理响应 ~0.3s (SITL Iris ~0.1s)
  - GPS/heading 噪声更大
  - 话题后缀需 _v1, VehicleControlMode 单源
  - 无 xy_valid (室内), 风/振动影响

--- 问题 F: 单目高度估计根本局限性 ---

单目相机 + 已知高度 -> 水平位置估计的精度高度依赖于:
  1. 高度 H 的准确性 (v6 已修复地面基准)
  2. 飞行中 pitch/roll 的实时准确性 (_cb_attitude 姿态补偿)
  3. heading 的准确性 (+-1.5deg 随机误差无法消除)
  4. pinhole 模型在广角边缘的畸变

在 4m 高度 85deg HFOV 下，heading +-1.5deg @13m = +-34cm 随机误差
即使所有系统误差消除，单目定位的随机误差下限约 30-40cm (1 sigma)

## 一、对核心架构的确认

v6 的 12 状态机设计是经过多次迭代后的收敛版本，我确认以下几个关键设计的逻辑正确性：

**1. 几何身份锁（NED 最近邻）**
```
_cb_detect 遍历所有检测 → 每个检测做 ROI→NED → 与 _current_target_ned 比较 → 取最近的那个
```
这比旧版的"nearest-center"方案高明在哪：
- 旧版：谁离图像中心近就选谁，但桶在图像中的位置会随飞机位置变化，同一个桶可能从中心移动到边缘 → 身份混淆
- 新版：谁离已知的 NED 坐标近就选谁，NED 坐标是固定的，不随飞机位置变化 → 身份稳定

**2. 位置增量控制替代速度控制**
```
PID(像素偏差) → 体轴速度 → 位置增量(v*dt) → _pub_pos(新位置)
```
这是针对 PX4 SITL 低速速度跟踪差的务实方案。PX4 位置控制器是经过严格验证的，让 PX4 自己去处理"怎么到达这个位置"，比我们自写速度 PID 平滑得多。

**3. Yaw 分层管理**
- 盲飞阶段 yaw=heading0（锁定航向，保证直线飞行）
- 视觉伺服阶段 yaw=live heading（让机头自然跟随，不干扰 PID）

这个分层设计保证了盲飞的直线性，同时在视觉伺服时不过度约束姿态。

## 三、对当前面临问题的评估

### 问题 A：几何身份锁阈值太宽（P0，低修复成本）

你的分析完全正确。当前 `GEO_IDENTITY_MAX = 2.5m`，而 B2-B3 间距仅 2.2m < 2.5m。

**风险场景**：当前目标桶是 B2 (NED=2.00, 13.00)。B2 丢检测时，B3 (NED=0.00, 14.00) 的 NED 估算可能因为噪声偏移到 `B2 + 2.2m ± 0.4m` 范围内。如果偏移方向恰好向着 B2，就可能通过 2.5m 的身份锁 → 跟错桶。

**你建议的 1.5m 阈值**（3.8 sigma）是正确的：
- ROI→NED 误差 ~39cm RSS，1.5m ≈ 3.8 sigma，误拒率 ≈ 0.02%
- 1.5m < 2.2m（最小桶间距），两个桶的 NED 估算不可能同时进入对方身份锁
- 即使遇到极端噪声（3.8 sigma），也只误拒不误收（fail-safe）

**建议**：改为 `GEO_IDENTITY_MAX = 1.5`，`POSITION_REFINE_IDENTITY_MAX = 1.5`（保持一致）。

---

### 问题 B：APPROACH 隔离不可靠

你的担忧很合理。"被动等待 FOV 缩小"确实不可靠，原因你已经分析得很清楚。

**替代方案建议**：

**方案 1：直接飞向目标桶，跳过 APPROACH 隔离**
- POSITION_REFINE 修正坐标后，直接用 `_pub_pos` 位置控制飞到目标桶正上方，然后下降
- 当你已经知道桶的 NED 坐标（误差 < 0.5m），飞到它正上方的途中，另一个桶自然会移出 FOV
- 4m 高度时飞到桶正上方，FOV 水平覆盖 ±3.4m
- 桶间距 2-3m，当你飞到桶1上方时，桶2在 FOV 边缘或外面

**方案 2：主动平移隔离**
- 利用 `_current_target_ned` 和剩余桶的 NED 坐标，计算哪个方向平移能把相邻桶移出 FOV
- 小幅平移（1-2m），让相邻桶移出 FOV 后再下降

---

### 问题 C：B2 伺服精度差

v5 的 0.56m 误差是因为身份混淆（投到了 B3 而不是 B2），不是伺服精度问题。
v6 的 H 修复 + 全选桶 + 收紧身份锁后，B2 应该被正确识别。

**但你说得对，第二个桶的 VISUAL_SERVO 时间可能受限**。整个流程 B1 约 24s + CLIMB 10s = 34s，B2 从第 34s 开始。VISUAL_SERVO_TIMEOUT=35s 应该是够的，但需要实际测试验证。

---

### 问题 D：位置增量无界漂移

这是 `_pub_pos` 位置增量方案的一个内置风险。因为 `_servo_target` 通过增量无限累加，没有与原始锁定坐标的约束。

**建议修复**：
```python
# VISUAL_SERVO 阶段，每次更新 _servo_target 后：
tx, ty = self._current_target_ned
if math.hypot(_servo_x - tx, _servo_y - ty) > 2.0:  # 漂移超过 2m
    # 软约束：向锁定坐标拉回 50%
    _servo_x = 0.5 * (_servo_x + tx)
    _servo_y = 0.5 * (_servo_y + ty)
    self.get_logger().warn(f"SERVO drift exceeded 2m, pulling back")
```

---

### 问题 F：单目高度估计根本局限性

这个分析非常到位。**单目视觉 + 已知高度 → 水平位置估计的精度确实有物理上限**。

你推导的 +-39cm 随机误差（1 sigma）是合理的：
- heading ±1.5° @13m → ±34cm
- YOLO bbox ±10px → ±14cm  
- pitch ±1.5° → ±13cm
- RSS ≈ 39cm

但这 39cm 误差对投放精度的影响取决于：
- VISUAL_SERVO 阶段飞机已经在桶正上方 1-2m，此时水平误差被像素伺服消除
- 所以 ROI→NED 的主要用途是 **HOVER_SEARCH 选桶 + POSITION_REFINE 初修正 + VISUAL_SERVO 身份确认**
- 最终精度依赖的是像素伺服，而非 NED 估算

**换句话说**：NED 估算的 39cm 误差用于"粗定位"（找到桶、飞到桶附近），像素伺服负责"精定位"（飞到桶正上方）。这两个是互补的，不是互相替代的。
