# 日志分析与误差归因

## 一、三种日志

| 类型 | 谁产生 | 在哪 |
|---|---|---|
| **节点日志** | 机载节点 stdout | `~/fly/log/k_<时间戳>.log`（`k.sh` 自动落盘）|
| **飞控日志（ULog）** | PX4 | QGC 下载，`.ulg` |
| **仿真产物** | `test_k.sh` | `runs/k_<seed>_<时间戳>/` |

**【经验/建议】必须配合看**：节点日志说"节点认为发生了什么"，
ULog 说"飞机实际做了什么" —— 很多结论只有**对齐两者**才能得出 ✓

## 二、一条命令分析

```bash
python3 scripts/analyze_k_flight_20261013.py <日志> [--ulog <x.ulg>]
```

**输出**：每投的粗对准、释放行、**触发方式**、残差统计、最好的一刻，
最后给出结论 `能满足 3cm/2.0s 的投放 n/N` + 一棵决策树 ✓

## 三、⚠️ 三个必须避开的坑

| 坑 | 说明 |
|---|---|
| **不能看 `win=`** ✗ | `win` 是"**到达后已等待时长**"（3.0 s 后容差放宽 +3 cm），不是"3 cm 保持 2.0 s"那个窗。**判定要看 `触发方式=`** ✓ |
| **不要用残差序列重建判据** ✗ | 日志节流 0.5 s，**释放快时一行都不打** ⇒ 会误判"样本 0 个 = 不满足"（实际那是最理想的情况）|
| **编号基准不同** | `进入 DROP #N` 是 **1-based**，`>>> DROP #N!` 是 **0-based** ⇒ 别自己 `+1` ✗ |

## 四、★ 误差归因

```
落点距真桶心 = 释放残差 ⊕ 桶估计误差
              (我们可控)   (参照系的误差)
```

**【实测数据】** 22 投统计：

| 项 | 中位 | 最坏 |
|---|---|---|
| **释放残差** | **1.85 cm** | **2.90 cm** |
| 桶估计误差 | 2.50 cm | 6.11 cm |
| 合计（落点）| 3.34 cm | 8.31 cm |

**桶估计误差 ≈ EKF 位置误差**（因为视觉是准的）：
- 某时刻 EKF 位置距真值 **2.1 cm**，像素 2 px 换算 **2.1 cm** ⇒ **两者一致，视觉准** ✓
- 释放瞬间 EKF 距真值 **8.3 cm** ⇒ **误差在 EKF** ✗

## 五、三个口径

| 口径 | 怎么读 | 能说明什么 |
|---|---|---|
| EKF 口径 | `/drop/impact_rel` | 环路在 EKF 帧内是否自洽 |
| 真值口径 | `GT_JUDGE=1` ⇒ `/drop/impact_gt` | SITL 里的真实几何 |
| **释放残差** ★ | 释放行的 `残差=` | **唯一能预测实机精度** |

## 六、决策树

| 结论 | 含义 | 下一步 |
|---|---|---|
| ✅ 全部"达标即投" | 判据够用 | 去标定补偿 |
| ⚠ 部分达标 | 残差**没进过门限**（稳态精度）/ 进过但**保持不住**（飞机停不下来）| 看 ULog 的静定占比 |
| ✗ 全是兜底 | 判据偏紧 | 归因 → 若是摆动就延长稳定等待/降下降末速 |
