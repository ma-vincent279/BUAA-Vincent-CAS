# SITL —— 仿真环境

这里放**仿真相关的一切**：代码、场地、模型、脚本、配置，以及**整套可运行的工作空间快照**。

> 本项目的仿真是 **PX4 SITL + Gazebo Harmonic (gz-sim8) + ROS 2 Humble**。
> 详细搭建步骤（含要输什么指令）见 [`../技术文档/配置仿真环境.md`](../技术文档/配置仿真环境.md)。

## 里面有什么

| 目录 | 内容 |
|---|---|
| **代码/** | 仿真侧全部节点 |
| ├ 任务节点/ | **主任务状态机**：`a` ~ `k` 全套历史版本（`k` 是当前主线）|
| ├ 检测器/ | 视觉检测（仿真 GT 投影 / YOLOv8）|

| ├ 工具/ | 悬停探针 / 真值记录器 / 舵机测试 / 桥接 |
| ├ 工程脚本/ | 项目生成器（从旧版本生成新版本，带锚点断言）|

| **脚本/** | 一键启动 / 清理 / 场地生成 / 跑分 |
| **场地/** | `.world` + `.truth.json`（**同一次生成**，桶坐标唯一来源）|
| **模型/** | Gazebo 模型（x500 我们改过质量惯量与相机）|
| **配置/** | PX4 参数、模型配置 |
| **工作空间/** | ★ **整套打包** —— 完整可运行的工作空间（照搬环境里的命名 `src/` 等）|

## 怎么跑

```bash
# 在仓库根目录（顶层 src/ 是本地运行的工作空间）
colcon build --packages-select drone_drl
source install/setup.bash

python3 scripts/test_k_servo_20261011.py     # 离线验收 104 项
bash scripts/test_k.sh                       # 跑一轮（默认 Gazebo Harmonic）
bash scripts/cleanup_sim.sh                  # ⚠ 每轮前必清进程
```

## 三条必知的坑

| 坑 | 现象 | 怎么办 |
|---|---|---|
| 残留 `gz` 进程 | 下一轮 `Task already running`，**飞机起不来**、0 投 | `bash scripts/cleanup_sim.sh` |
| 世界文件里声明 gz system plugin | `Found 0 compass` / `barometer missing` | **世界里不要声明**（由 `server.config` 全局加载）|
| 世界缺 `<spherical_coordinates>` | `Preflight Fail: Strong magnetic interference` | 补上 |

## ⚠️ 重要认知

**仿真的分数不能代表真实精度** —— 原因是结构性的：
SITL 的"落点"取飞机自报的 **EKF 位置**，而仿真检测器也是**用 EKF 造框**的
⇒ 整条视觉链对 EKF 的绝对估计偏差**结构性失明**。
所以 **SITL 分数只用来判"链路是否正常"，量精度要看「释放残差」**。
详见 [`../技术全解.md`](../技术全解.md) 第三节。
